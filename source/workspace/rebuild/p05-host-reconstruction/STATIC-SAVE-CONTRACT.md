# P05 ordinary save/load consistency

This integration protects correct displayed-source receipts and ongoing menu continuation. It is not a general hostile-save or damaged-engine security system.

## Trusted data and comparison

Text resources 240 and 241 are newly allocated readable decimal tables, generated from the accepted scene982, accepted Contest scene route table and preserved MusicTransport981 source. They contain 20 unsigned SCI16 words per entry, five decimal digits plus a space for each word. The named map is `generated/static/manifest.json`; no opaque compiled data or checksum is used for runtime equality. Resource242 contains the canonical, normalized VC menu/reply labels and short IR navigation IDs.

Current resource maps and retained reservation snippets contain no text240–242 allocation. The whole-universe builder rejects any collision with the preserved static resource set. Views240–242, if later assigned, are a distinct SCI resource type.

On the first replay hook, the host reacquires script exports, cancels presentation audio, and compares every saved static word against a newly loaded packaged entry. Any mismatch quarantines ordinary input, suppresses reader/audio and returns before the original replay can use transport or scene metadata. The exact original mutable puzzle words, current/target music gains, event/reader queues and text buffers are not treated as canonical static tables. There is no saved validation flag or trusted saved cache.

The seven scene array families, one route array and twelve music arrays are covered. Contest986 tier, accepted-answer and canonical-record mappings are compiled methods with literal constants, not serialized initialized tables. Its dynamic decks, expected-record scratch and candidate buffers retain the accepted r2 validation/recomputation protocol.

Scene route/page access additionally checks the exact current document/count/page tuple/text/audio/duration entries before loading text. A matched VC route checks all seven words against its packaged row, preventing a setup receipt from being redirected to a reply or a unit alias from being widened.

## Buffers and normal packaging boundary

A static entry is exactly120 bytes plus NUL and uses a128-byte scratch buffer. The generator and public pre-build input validator require exact source-derived bytes, entry count, grammar and word values. The runtime parser bounds table/index/count and each digit. Malformed or overlong package data is rejected before packaging; the runtime assumes its pinned packaged resources are intact. This does not claim resilience to arbitrary replacement of the running resource manager or oversized native resources.

All61 canonical menu/reply/navigation buffers are initialized from resource242. Replay compares the saved buffer words against fresh expected text before any getter may reload them. Menu IDs, pointer identity, enabled/selected values, page extent and domain phase are also validated. A pending response may legitimately use confirmation218 or Back/Close continuation217; neither path scores or clears the pending domain choice.
