This packet implements a new reusable numeric domain, readable source, exact canonical binding tables, a strict logical word codec, candidate transactions and compiler/test evidence. It does not integrate into Main or constitute a playable build. Do not splice its independent binaries into another game. Recompile the complete selected source universe after an independently reviewed host integration.

## Pending boundaries and user intent

The host must honor SETUP_PENDING, RESPONSE_PENDING, FEEDBACK_PENDING, KO_PENDING and RESULT_PENDING exactly. Choosing a response persists a pending choice without scoring. Committing scores once and freezes feedback. The queued reply is separate from feedback. Every result requires the generic result plus each separately bound concession/flourish speech unit, and prior-win explanation when applicable. A rematch cannot skip them.

RESULT_PENDING is a mandatory campaign barrier: do not use newly committed RESOLVED as permission to hide the concession behind a loan, room transition, another actor interaction or ending action. Menus, mute, pause, save and load may preserve it. The isolated API blocks its own new attempts/lessons/intros; the native host must block unrelated actions too.

Explicit exchange yield and explicit contest yield are separate actions. Close, audio skip, mute, room changes, save/load and menu buttons must never be translated into either. Audio completion is never a learning receipt, score trigger or implicit user choice.

## Whole-VM restore, callbacks and persistent state

A callback captures all token fields, including generation and exact logical event kind/slot. The140-word envelope persists only logical history/knowledge/attempt/text state. A newer host generation is required at both initial and final restore checks; the port reproduces the accepted queued-restore race protection. A failed numeric load preserves the live state and generation. A successful load replaces the complete timeline, suppresses all already committed effects, and preserves queued text/choice/deck/cursor.

These numeric checks do not make ordinary SCI memory process-global. RestoreGame can roll back every property, local and global that the VM stores. Before any old callback resumes, the host must establish a fresh owner outside the restored event graph or prove total stale-callback retirement. It must synchronously clear pending renderer/page callbacks, PCM/audience tasks, timers, poses and dispatch work. vcAfterRestore blocks input pending a fresh generation but cannot itself cancel an external task. Merely incrementing restored memory is insufficient. No UUID, randomness or uniqueness guarantee is invented. Generation exhaustion is fail-closed, requiring an explicit reviewed migration/rebuild policy.

## Campaign/P05 atomicity

Successful operations prepare a hidden candidate. The campaign owner must atomically persist it with the actual host state and call vcCommit only after definitive success. Readers retain the prior committed words while that hook runs. A failed non-commit uses vcAbort; an uncertain durable outcome enters fail-stop until loading the authoritative snapshot. vcAfterRestore cannot clear a live busy/uncertain transaction.

P05's loan request/receipt/ownership transaction remains separate. The host must compose P05 and Contest state into one authoritative save and respect the concession barrier before PA/cart handoff. Neither this port nor its tests claims successful P05 loan atomicity, complete inventory validation, or correctly moved actors/items. P05's separate session lease convention is not silently merged into Contest's bounded generation contract.

The accepted reference JSON/checksum codec and atomic writer are bundled as tested authority. The native140-word loader strictly rejects numeric state corruption, while exact schema/catalog identity, JSON type/key/size handling, disk durability and transaction storage are bridge/host responsibilities. No historical SCI save codec compatibility is claimed.
