## Exact virtual-to-physical mapping

The authority is the byte-pinned ScummVM v2026.3.0 source in p08-host-planning/runtime-2026.3.0, particularly kfile.cpp SHA256 6d6900b6e9fb5808606a4398153f44d4598d9639dc23e3b07e0178c761872e30. Its provenance links https://github.com/scummvm/scummvm/blob/v2026.3.0/engines/sci/engine/kfile.cpp. The official QA executable and package hashes are retained in the accepted P08-RUNTIME-CONTRACT.md.

CheckSaveGame takes virtual IDs 101 through 199 and subtracts 100 to inspect physical slots 1 through 99 (kfile.cpp lines 1308–1345). Each call invokes listSavegames itself. A true result means the physical slot has recognized metadata and a supported serializer version. The scan must stop at its first false result, N + 100.

GetSaveFiles first sets _lastSaveVirtualId to 100 (lines 1348–1353), then enumerates recognized saves and writes at most 20 descriptions/IDs (lines 1353–1382). Its capped output is used only for cache reset, never as the capacity decision. The exact buffers are 361 SCI words for names (722 allocated bytes, at most 721 written) and 20 register words for IDs. CheckSaveGame and the later allocator each enumerate the full recognized list independently; neither is limited by that 20-item output.

At the first false CheckSaveGame result for physical slot N, Format creates exactly *.NNN in a bounded buffer. FileIO(10,pattern) must return false. kFileIOExists checks regular files, then listSavefiles(name) with the raw glob before trying a target prefix (lines 872–883). Thus any incompatible/unreadable slot or ambiguous other-target match causes refusal. The host never skips the ambiguous first candidate or attributes the match to this game. No target name is guessed. SciEngine::getSavegameName in sci.cpp lines 892 onward constructs target.NNN; the raw suffix glob only proves candidate absence.

After that guard, SaveGame("cakood", 1, "BEGIN THE EVENING.") uses the generic script interface: non-null game ID and canonical non-null description. ID 1 is a low virtual ID, not a request to overwrite physical slot 1. kSaveGame enumerates the full recognized list at lines 1131–1133, takes its low-ID branch below 100, and for this actual fan-made cakood object reaches the generic allocation loop (lines 1185–1208). The prior cache reset makes _lastSaveVirtualId=100, so the requested 1 cannot select the cached-overwrite branch. The allocator selects the first absent physical slot from 1 through 99. All slots before N were recognized occupied and N was absent in both recognized and raw existence checks; therefore it selects the exact checked N. There is no intervening chooser or save operation.

For example, recognized physical slots 1 through 25 produce a GetSaveFiles count of 20, but CheckSaveGame(101) through CheckSaveGame(125) are true, CheckSaveGame(126) is false, and a false FileIO("*.026") permits the low-ID call to create physical slot 26. Sparse histories choose the first hole. Ninety-nine recognized slots or any raw match at the first hole refuse before SaveGame. Every retry repeats cache reset and the full bounded preflight. Existing manual saves are not overwritten, deleted or renamed. The proof assumes the ordinary single-threaded game sequence and must still be tested on the stock native save-file manager; concurrent external modification is not claimed to be locked by SCI.

## Request, attempt and restore authority

The ordinary advance/route gateway will service one deferred attempt only after a completed composed scene, no current input/menu/movement/reader, complete owner/queue/campaign validation and existing audio-save preparation. Final Yes captures request, current revision, session lease, route epoch and a bounded non-wrapping attempt generation. One queued attempt becomes in-flight once; failure, ambiguity or full capacity becomes pending retry, never a per-frame write loop.

The return value must be exactly true and every captured identity must still match before a host success receipt is published. Actual p08AcknowledgeAutosave and E03 stay disabled in this gate. Manual chooser returns, file existence and CheckSaveGame results confer no completion authority. Normal save preparation uses the existing speech/foley retirement and musicBeforeChooser/musicAfterChooser methods; it must not save with h8Critical set.

The pre-transition file contains phase 3 and an explicitly validated in-flight attempt. Ordinary restore validates the raw descriptor before older inventory publishers, retires queued/in-flight/success authority, increments the saved attempt generation, rebinds the new admitted session and exposes only a fresh explicit retry/cancel. A returned continuation from an abandoned timeline cannot match the new attempt. Literal p08RetryAutosave is used for each explicitly requested retry, preserving the same confirmed request while advancing its revision. Canonical BEGIN THE EVENING. and NOT YET. remain the only menu words; Begin is enabled for a failed/restored pending attempt, not for queued/in-flight/success state.
